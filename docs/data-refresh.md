# Data refresh procedure

## Reviewing a source

1. Open the official source and confirm it supports the exact record fields.
2. Check whether dates, contacts, fees, venues, requirements, and schedules are
   still current.
3. Edit the appropriate JSON record in `src/data`; keep an empty `sourceUrl` if
   no supporting source is available.
4. Keep `verification: "unverified"` and `lastVerified: null` until Caleb has
   completed the source review. Only Caleb enters the verification date and
   changes the state to `verified`.
5. Run `npm run check`. The audit reports but never changes data.

Never treat a URL or a successful build as proof of accuracy. Do not turn a
sample barangay into a real record by changing its label.

## Importing barangays

The user must obtain the official barangay list from PSA PSGC and the 2020
Census tables. Save the UTF-8 CSV at `data-source/davao-barangays.csv` with
these exact columns and header order:

```text
name,adminDistrict,legislativeDistrict,population2020,sourceUrl
```

Administrative districts must match one of the eleven district names recorded
in `cityFacts.json`. Numeric columns can be blank; a nonblank value must be a
non-negative whole number. Source URLs must use HTTPS.

Run:

```sh
node scripts/import-barangays.mjs
npm run check
```

The importer writes every row as unverified, with a null verification date. It
rejects malformed rows, duplicate barangay slugs, and unknown districts. Keep
the source CSV available to the maintainer; it is not generated by the importer.
